# Test cases

What the Obsidian plugin does, said as things a person can check. One row per
behaviour, written so that someone who has never opened the code can run it.
It was section 14 of DBML Studio's `docs/test-cases.md` before the plugin moved
to this repository.

The diagram frame is DBML Studio's, in hosted mode: the plugin pushes the model
in with `document` and the theme with `theme`. It is delivered as one
self-contained document, its code inline, because Obsidian refuses the external
scripts of a document served from a plugin folder; the document travels gzipped
inside `main.js`, and the plugin writes it into its folder on the first start
after an install or update.

The wiring into Obsidian itself — windows, views, scrolling, the theme — is out
of jest's reach, so most of this list is manual, against a real vault.
`main.test.ts` covers what the plugin does with the blocks it is handed,
against a stand-in for the `obsidian` module. **Automated** names the test that
already covers a case; **Manual** means nobody has automated it yet.

Run the automation with `npm test`. Build and install into a vault for the
manual cases with:

```bash
npm ci
npm run build
npm run install:vault -- /Users/me/notes
```

Case 4 and the build above use the `dbml-frame` package pinned in
`package.json`; to try a frame that is not published yet, build the package in a
DBML Studio checkout and run `DBML_FRAME_SOURCE=<its packages/dbml-frame>
npm run build` (see the README, "The frame").
